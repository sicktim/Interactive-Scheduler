## Phase 1 — Small features

### 1a. Whiteboard time-entry UX
Root cause found: `WhiteboardCell` time-mode never focuses its `MilitaryTimeInput`
(focus effect at 6689 only reaches text inputs' `inputRef`; time input at 6764 gets no
ref/autoFocus), and Enter does nothing in time cells (`MilitaryTimeInput` keydown 6389–6397
swallows it; td-level handler 6741 only handles Escape/Tab).

- `MilitaryTimeInput`: accept `inputRef` prop + `onEnter` callback; attach ref; Enter →
  normalize (reuse blur logic) + `onEnter(normalized)`.
- `WhiteboardCell`: single focus effect for BOTH modes; **`.select()` on focus** (zero
  `.select()` calls exist today — this gives "click → highlighted → type immediately").
- Enter in time cells: commit + exit edit, caret stays (matches text cells).
- Tab: existing `makeTab` chains (Flying 7852–7858: Model→Brief→ETD→ETA→Debrief→Event→Notes;
  Ground 7984–7990; NA 8148–8154) already commit + move; the focus fix makes the landing
  cell actually editable. Tab on the LAST field in a chain: commit + exit (behave like Enter).
- Keep the T8 lesson: drafts stay local, commit once (WhiteboardCell already does this —
  re-sort only happens after commit, which is expected).

### 1b. Collapsible Change Summary
`.app-layout` is `grid-template-columns: 1fr 300px` (82); column 2 holds ONLY
`.change-summary-panel` (107–115, component 5462–5535, rendered 9329–9334).

- `summaryCollapsed` state in SchedulerView, persisted (`tps-scheduler-summary-collapsed`).
- Collapsed: `.app-layout.summary-collapsed { grid-template-columns: 1fr 28px; }`; panel
  renders as a slim vertical bar — chevron ◀ + rotated "CHANGES" label + count badge
  (amber when > 0). Click anywhere on bar expands. Light-mode styles for every new class.

### 1c. Adjustable academics times
Academics are synthesized `readonly:true` (3146–3164); `WhiteboardAcademics` (8062–8109)
renders times as plain `<td>` text (8101–8102) and receives no save handler (8576).

- Pass `onEditSave` into `WhiteboardAcademics`; swap the two time `<td>`s for
  `WhiteboardCell type="time"` with a `timesEditable` override (event stays `readonly` —
  crew editing and timeline exposure remain blocked; `handleEditSave` 8691–8711 has no
  readonly guard, so edits flow into ChangeSummary as `event-edit` automatically).
- Rows with no matched event (8095–8097): leave non-editable (nothing to save to).

CR B offset 30 min from its SY parent; identical-time unrelated GLIDER/T-38 clusters).
Timeline already pairs by "nearest preceding non-sim row" (`buildFlyingLayout` 3807–3819,
`SIM_CR_MODELS` 2764). The whiteboard Flying sort (8394: model → startTime) destroys row order.

- Parser: stamp `rowIdx` on flying/ground/NA events in `transformBatchData` (~3010).
- Pairing at parse: SIM/CR flying rows get `attachedTo: <parent event id>` via the
  preceding-row rule (single source of truth shared conceptually with buildFlyingLayout).
- Whiteboard sort toggle (in `.wb-date-header-row`): **Aircraft** (current) vs
  **Whiteboard** (rowIdx). In Aircraft mode, attached rows are spliced directly after
  their parent (sort parents only). Attached rows get a nesting visual (indent + └ tie,
  subtle left border in parent's tint). Persisted preference.

## Phase 3 — Big Board data service

Live GAS verified: `?call=sheets_avail` (47 sheets) and `?call=fetch_sheet&sheet=<name>`.
Target sheets exist as `26A FTC Big Board`, `***26A STC BigBoard***`, `26B FTC Big Board`,
`***26B STC BigBoard***` — resolve via `sheets_avail` pattern `/26[AB].*(FTC|STC)/i`
excluding `Backup_`, never hardcode.
Endpoint: `https://script.google.com/macros/s/AKfycbyU4XfKl5ct6SMzl1nh7e4yZOR6U_wqD9_4HbUNBUOm7fgUaJIPTUIH95CVEGsIfVmiUw/exec`

- **Status derivation: port `classifyCell` + `parseCellDate` verbatim** from MCG-Tracker
  `tracker/index.html` status.js (1375–1475) — it embeds hard-won fixes (day-precision
  comparison, past-date-still-scheduled v0.5.2e, ambiguous-year → null). States:
  darkGrey→notreq · lightGrey→complete · paired+strike→complete · paired→paired-opted ·
  white+date→scheduled (flag past-date-unchecked) · white blank→pending.
- **Cache**: derive-then-store compact form per class in `tps-bigboard-cache-v1`:
  `{fetchedAt, sheetName, classMeta, students:[{bb, last, initial, type}], byCode:
  {EVENTNO: {title, status: {studentIdx: {c, d?, f?}}}}}` (~120 KB/class; raw would be ~500 KB).
- **UI**: "Big Board" header button → modal listing the four classes with cached
  **"as of <fetchedAt>"** stamps, per-class Load/Refresh (30–60 s spinner), and a global
  **Reset Big Board Data**. Show unmatched-student diagnostics per class.
- **Student matching** (verified against live 26A FTC: `E MARTINEZ`, `E PETERSON, R`,
  `F GHESQUIERE *`): strip trailing `*`, strip leading track-letter token
  (C/R/E/A/F/B/M), optional `, X` initial; whiteboard `Last, F *` → last + initial;
  scope to the mapped roster category (26A FTC→FTC-A, 26A STC→STC-A, 26B FTC→FTC-B,
  26B STC→STC-B); last-name unique match, initial tiebreak, else report unmatched.
- **Event matching**: whiteboard title `Name (CODE)` → regex `\(([A-Z]{1,3}\s*\d{3,5}[A-Z]?)\)`,
  normalized uppercase/single-space ↔ `eventNo` (223/262 events on 26A FTC carry one).
  Only matched events get Tab-1 content — per scoping rule.
- **Standing rule from MCG-Tracker AGENTIC.md**: the Big Board is NOT authoritative for
  *applicability* (MCG is). We use BB only for scheduled/completed status; `notreq`
  (darkGrey) students are hidden behind a "show N/A" toggle rather than asserted as
  truly not-required. Document this in AI-CONTEXT.md.
